File Handling in Shell Scripting: Reading and Writing Files

A practical guide to standard streams, redirection operators, safe line-by-line file parsing, and automated log reporting in Bash.

1. Introduction

In UNIX and Linux systems, almost everything is represented as a file—whether it is a plain configuration document, a system log, a directory, or a hardware device. Because of this design philosophy, knowing how to read from and write to files is one of the most practical skills you can build when learning shell scripting.

While commands like cat, echo, and terminal editors such as vi are fine for quick manual edits, real administrative work relies on repeatable scripts. Whether you are archiving daily server logs, cleaning up raw data exports, or scanning authentication records for unauthorized login attempts, shell file handling lets you automate routine tasks cleanly without manual intervention.

2. Concept Explanation

Every command executed inside a Linux shell communicates through three default input/output channels known as standard streams:

  • Standard Input (stdin, File Descriptor 0): Data fed into a program, usually from the keyboard or a redirected file.
  • Standard Output (stdout, File Descriptor 1): Normal output produced by a command, printed to the terminal by default.
  • Standard Error (stderr, File Descriptor 2): Diagnostic or error messages generated when something goes wrong.

File Redirection Operators

Shell scripting handles file creation, overwriting, and reading by redirecting these streams using built-in operators:

Operator Purpose How It Works
> Write / Overwrite Creates a new file if it does not exist, or replaces all existing contents if it already exists.
>> Append Adds new output to the end of an existing file without erasing previous lines.
< Input Redirection Feeds the contents of a file directly into a command or loop as standard input.
<<EOF Here Document Writes a clean multi-line block of text into a command or file until the closing EOF marker is reached.

Reading Files Safely Line by Line

When reading a file inside a Bash script, combining a while loop with IFS= read -r is the cleanest and safest pattern:

syntax_pattern.sh 
while IFS= read -r line; do
    echo "$line"
done < "input.txt"

Setting IFS= (an empty Internal Field Separator) keeps Bash from trimming leading or trailing spaces on a line, while the -r flag prevents backslashes (\) from being treated as escape characters. Redirecting the file at done < "input.txt" also avoids spawning an unnecessary subshell.

3. Practical Demonstration

To see both file reading and file writing working together, let us build a practical script called log_analyzer.sh. The script generates a sample authentication log, reads through it line by line, filters out failed login attempts, and writes a clean security alert report.

Step 1: Shell Script Code (log_analyzer.sh)

log_analyzer.sh 
#!/bin/bash

# Define input and output file names
LOG_FILE="auth_events.log"
REPORT_FILE="security_alert_report.txt"

# 1. WRITING TO A FILE: Create sample log data using a Here Document (>)
cat <<EOF > "$LOG_FILE"
2026-11-21 09:12:04 INFO User 'admin' logged in from 192.168.1.10
2026-11-21 09:15:22 FAILED_LOGIN Invalid password for 'root' from 203.0.113.45
2026-11-21 09:18:40 INFO User 'tirth' accessed /var/www/html
2026-11-21 09:21:11 FAILED_LOGIN Invalid password for 'admin' from 198.51.100.19
2026-11-21 09:25:00 FAILED_LOGIN Brute-force threshold warning from 203.0.113.45
EOF

echo "[+] Sample log file '$LOG_FILE' created successfully."

# 2. INITIALIZING OUTPUT REPORT: Overwrite (>) to start a fresh report
echo "==========================================" > "$REPORT_FILE"
echo "   AUTOMATED SECURITY ALERT REPORT" >> "$REPORT_FILE"
echo "   Generated On: $(date)" >> "$REPORT_FILE"
echo "==========================================" >> "$REPORT_FILE"

# 3. READING FROM A FILE: Parse line-by-line using while + read
failed_count=0
line_num=0

while IFS= read -r line; do
    ((line_num++))
    if [[ "$line" == *"FAILED_LOGIN"* ]]; then
        ((failed_count++))
        echo "[Line $line_num] ALERT: $line" >> "$REPORT_FILE"
    fi
done < "$LOG_FILE"

# 4. APPENDING SUMMARY FOOTER: Append (>>) total count
echo "------------------------------------------" >> "$REPORT_FILE"
echo "Total Failed Login Attempts Detected: $failed_count" >> "$REPORT_FILE"

echo "[+] Analysis complete. Report saved to '$REPORT_FILE'."
echo ""
cat "$REPORT_FILE"

How the Script Works

  1. Creating Sample Input (cat <<EOF > "$LOG_FILE"): Writes five realistic server event lines into auth_events.log in one step.
  2. Initializing the Report (> and >>): Uses > on the first header line so any stale report from an earlier run is cleared, then switches to >> for subsequent lines.
  3. Line-by-Line Inspection (while IFS= read -r line): Reads auth_events.log sequentially, tracks each line number with ((line_num++)), and checks whether FAILED_LOGIN appears in the entry.
  4. Writing the Summary: Appends every matching alert along with its line number and writes the final count at the bottom of security_alert_report.txt.

5. Real-World Applications

  • Cybersecurity & Log Auditing: Security teams routinely use lightweight shell scripts to monitor /var/log/auth.log or web server access logs, isolate repeated failed SSH login attempts, and append suspicious IP addresses to firewall blocklists.
  • Automated Backup Routines: System administrators schedule cron jobs that read directory paths from a configuration file (backup.conf), archive critical data, and write timestamped completion logs for compliance tracking.
  • Data Cleanup & Preprocessing: Developers use Bash file loops to normalize raw CSV or text dumps, strip malformed records, and generate clean output files before loading data into databases.

6. Conclusion

Reading and writing files sits at the center of practical shell scripting. By combining standard redirection operators (>, >>, <) with safe line-by-line loops (while IFS= read -r), you can turn static log files and raw text into automated reports with just a few lines of Bash. Understanding these building blocks makes everyday Linux administration faster, cleaner, and far less error-prone.
